# R32 pre-registration (Claude Code, 27 Oct 2026): strict-blind fixed-alphabet search with K3-style rearrangements

Written before any R32 scan. It follows ChatGPT's R31 strict-blind contract (`archive/2026-10-27_chatgpt_R31_strict_blind`):
discover without the clues, freeze, then reveal.

## Contract
- **Blind program:** `blind/blind_route_scan.cpp`. It reads only:
  - the 97-letter ciphertext;
  - the quadgram table `data/quad_log10.f32`;
  - a key source text (letters only);
  - a route file.

  It contains no clue letters, clue positions or masks, and no oracle. Ranking is by the unchanged English quadgram
  sum over the 97 output letters.
- **Route file:** generated by `blind/make_routes.py` from K3's geometry rules only, the same R27 constructor as
  `k4common.route`. No clue information is used to choose, order or drop routes.
- **Freeze:** each run writes its top 100 (TSV), and `sha256sum` goes into `FROZEN.sha256` before any reveal code
  runs.
- **Reveal** (`sealed/`, run only after the freeze):
  - re-encrypt every frozen row forward to its input ciphertext under its stated method;
  - count clue matches (0–24) for the frozen rows;
  - a separate whole-family program counts clue matches for every setting, with the histogram and max.
- **No external submissions.**

## Families (K4, original ciphertext)
- **Conventions:** plaintext alphabet ∈ {AZ, KRYPTOS} × ciphertext alphabet ∈ {AZ, KRYPTOS} × operation ∈
  {Vigenère c = p + k, Beaufort c = k − p, variant Beaufort c = p − k} = 12.
- **Rearrangements (F1):** identity, plus the 20 R27 routes (`k4common.R27_ROUTES`) in both orders. 41 route-orders.
  - S_then_T: substitute in plaintext order, then rearrange, CT[j] = X[perm[j]].
  - T_then_S: rearrange the plaintext, then substitute in carved order, X[j] = P[perm[j]], CT[j] = sub(X[j], k_j).
- **F1 key sources:**
  - **CARTER:** `carter_az.txt` (sha256 6761a507…, the R30/R31 normalisation of Carter & Mace 1923 vol. I).
    Every window, forward and reversed text, key letters numbered by AZ or by KRYPTOS.
  - **K1K3:** `data/k1k3_plaintext.txt`, with the same window, direction and numbering choices.
  - **G5:** 5-digit chain addition, all 100,000 primers.
  - **C6:** 6-digit chain addition, all 1,000,000 primers.
- **F2:** K3-style double rotation `R{w1}x{w2}/{CW|CCW}/{fwd|inv}` for every w1, w2 ∈ 4..28 (2,500 routes), both
  orders, G5 keys only, the same 12 conventions.

## Positive controls (identical blind scans, true plaintext never read by the scanner)
- **F1:** 6 planted ciphertexts from `reference_messages.json` `r20_templates[0..5]`.
  - Each has a random route-order from the 41, a random key family (CARTER, K1K3, G5, C6, cycling), a random
    window or primer, and random conventions.
  - Seed 32001. Generated by `sealed/make_plants.py`.
- **F2:** 1 planted ciphertext (`r20_templates[6]`) under a random F2 route and G5 primer, seed 32002.
- **Success:** the true plaintext is ranked #1 in its family's frozen top 100. A control failure is reported and
  qualifies the K4 result; nothing is re-tuned.

## Decision rule (fixed now)
- **Candidate:** any frozen top-100 K4 row with 24/24 clue letters, or any setting counted 24/24 by the
  whole-family program. Its raw 97 letters go to Tyler; no external submission.
- Otherwise the result is "no candidate". The family is **EXCL** for these fixed conventions if the whole-family max
  is below 24.
- Partial clue matches are chance-level unless they clearly exceed the binomial expectation for the number of
  settings. They are reported, never "repaired".

## Not in scope
- Free (unknown) alphabets. A blind solver for those failed its gate in R30/R31 (L109, L112). A Claude Code
  development probe this round showed why: on planted data, hill-climbed wrong cipher alphabets reach a higher
  repeat rate than the true one (0.076–0.092 vs 0.061–0.072).
