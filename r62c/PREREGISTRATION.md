# R62C — independently preregistered COL_LT stage-1 gap calibration

**Locked 2026-11-02 before new null generation, new R61 stage-one execution or alternate-route search.** This is a no-K4-known-plaintext exploratory test of an observation first selected AFTER looking at R61 outputs. It is not confirmation of a K4 decryptor, key or route. Follow `r53/BLIND_RULES.md`. No external checker, main merge or clue-conditioned key searches.

## Fixed statistic and historical reference
For a given ciphertext and a ten-permutation route family, undo each route, run **unchanged** R59 solver with the exact R61 stage-1 parameters (BEAM=30000, TOPN=2000, LAMBDA=1, four AZ/KRY VIG/BEAU conventions, POLISH=0, POLISH_WORDS=20000), then retain each route's best **total**. Statistic G=highest route score minus second-highest, allowing ties and sorting by a deterministic route index for tie ranking. R61 original stage-one K4 historical top was COL_LT -313.7666, second R24x8/CW/inv -334.9797; G0=21.2131. This threshold was selected retrospectively and the prior 100 nulls are exploratory only. **We must recompute G0 under the exact same rebuilt source and model before comparisons.** If contemporary G0 differs from historical 21.2131 by more than 0.0002, classify original vintage binary mismatch and DO NOT assert commensurable calibration. Preserve all raw outputs regardless.

## Preregistered inputs, routes and nulls
Use the unchanged canonical K4 ciphertext file `r39/ic_gate/k4_ciphertext.txt` raw SHA256 including LF `2797de1451ab97118211735dcef370fc5acd70829f164aa043c47cbf40f0a5a3`. Extract only original 97 A-Z letters, no known plaintext files, words, offsets, R52 survivor keys or crib-conditioned routes.

1. K4 original 10 routes from `r61/routes.txt` and **20 alternate ten-route families** with fixed offsets s=1,...,20: preserve the original four K3 24x8 permutations; for the other six engraved-site routes, compute `perm_s[j] = (perm_0[j] + s) % 97`. Each is a permutation; no K4 outcome can influence these offsets. Test genuine ciphertext on original plus 20 alternatives.
2. **300 fresh frequency-preserving K4 shuffles**, deterministic `random.Random(620640)`, resample any duplicate or original. For nulls use **only the original ten routes**. Do not use R61's prior seed 610070. No extra nulls selected based on outcome.
3. Total 321 cases: 21 genuine ciphertext × route family variations, 300 nulls × original family. For computation shard with rule `case_index % 12` (12 independent Actions jobs), preserving exact case-index/ciphertext/route-shift manifest. Each shard runs stage one only and captures **all 10 × 13 per-route complete 97-character plaintext and key outputs**; stage-one route results from `r59/blind/rk_solve.cpp` include best, per_convention and top-8, not only best G.
4. Source/model pinning: `r59/blind/rk_solve.cpp`, `r61/routes.txt`, `k4kit/data/word_model_orth.tsv`, 23,373,368-letter R59 training corpus built from the 20 pinned books and 5 NLTK packages in `r59/corpus/build_corpus.py`, LM SHA `b1a2a3c777dafd6eadc277ee50eb988858253a7843fedfc6903700c61a92a85a`. C++ binary SHA may vary with compiler flags/platform; preserve compiler version and actual SHA; exact same newly rebuilt binary must be used for original and nulls. If G0 does not match historical, historical comparison cannot be claimed reproduced.
5. Each shard stores source/result hashes and raw full 97-letter pairs. Upload shard evidence to GitHub Actions artifacts, then a **single aggregate freeze job** checks 321 unique input IDs and all 10×13 full candidates, REMOTELY commits complete originals/nulls, exact key streams and hashes and provenance to review branch **before** ANY separate statistical evaluation. No reader in a prefreeze stage may access public known-letter positions or any postfreeze clue evaluator. C **does not** perform any K4 plaintext-letter check at all.
6. A separate after-remote-freeze job, only after confirming frozen commit/tree, recomputes every one of the **321×10×13=41,730** raw candidate 97-letter forward witnesses using a separate Python encryptor (tableau then record-specific permutation) and the exact source SHA chain; it reports originals vs nulls, **no** public K4 clue validation.
7. Compare original computed G0 to 300 fresh null G under the exact 10 original routes: corrected descriptive empirical rank `(1+# nulls with G>=G0)/301`, and 95th/99th null quantiles. Report binomial interval. Compare 20 alt-family genuine-K4 G to G0 (count >=G0 over 20). The alt family offsets share structure and are correlated, so this is *not* a genuine familywise-corrected p-value for arbitrary route searches. The original contrast is posthoc. Negative result remains informative about this exact statistic only.
8. **Decision preregistered:** send for physical mechanism/source hunt only if fresh-null empirical rank <0.01 AND fewer than 5% of alternative 10-route families have G as large as original, AND contemporary G0 matches original R61 historical 21.2131 within 0.0002. Otherwise classify anomaly as unsupported/chance-compatible under this limited calibration; no claim of universal cipher exclusion.

## Scope and limitations
Plaintext/K4 key derivation is never attempted by this experiment. A high G among wrong-language-looking decoded candidates is **not** a solution. A per-route F optimization automatically produces valid re-encryption witnesses even for ciphertext shuffles: witness validity does not prove a method is true. If any workflow fails, save exact error and partial artifacts; do not silently lower beam, change G statistic/alternative routes, or use a different LM. No merge and no K4 answer checker. R62B tests independent modern-English running-key power; it is a distinct experiment, and must not be used to retroactively tune the R62C route family/statistic.
